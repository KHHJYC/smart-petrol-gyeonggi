# 스마트펫트롤 · 우리동네 안전지킴이

경기도 공공데이터로 CCTV·보안등을 탐색하고, 반려견과 산책하며 시설 상태를 관찰·기록하는 공모전 웹 프로젝트입니다. 기존 다른 프로젝트와 독립된 GitHub Pages 배포본입니다.

[스마트펫트롤 웹사이트 열기](https://khhjyc.github.io/smart-petrol-gyeonggi/)

**2026-09-08 배포 상태:** 공개 사이트가 정상 응답합니다. GitHub에서 네 API 전체 수집도 확인했으나, 새 CCTV API 응답의 유효 좌표가 80,546건에서 2,606건으로 줄어 갱신을 차단했습니다. 지도는 좌표가 정상인 마지막 검증 자료를 유지합니다. 현재 API 누락을 시설 철거 또는 안전함으로 해석하지 않습니다. 원자료 좌표가 회복되면 다시 수집·검사한 자료를 게시할 수 있습니다.

## 웹에서 할 수 있는 일

- 31개 시군 선택, 동네·주소 검색, CCTV 목적 필터, 지도 표식 상세 조회
- CCTV·보안등이 주변보다 적게 등록된 약 250m 구획을 노랑~주황 그라데이션으로 확인
- 시설 점검 후보 위치 목록과 지도 이동, 선택 위치의 반경별 시설 수와 직선거리
- 카카오맵·네이버지도·구글맵과 로드뷰로 선택 장소 확인
- 반려동물 등록 통계, 조명 종류와 전력 구간별 설치 개소 수, 조명 연구 근거
- 순찰 시간 측정, 현장 기록, 확인 근거와 상태 변경, JSON·CSV 및 인쇄/PDF 출력

공용 기록 데이터베이스를 연결하면 현장 기록과 순찰일지는 저장하는 즉시 모든 이용자에게 공개됩니다. 작성자는 공개되지 않고, 다른 사람의 순찰일지는 정확한 시각 없이 날짜만 보입니다. 데이터베이스 설정이 없으면 기록은 현재 브라우저에만 저장됩니다. 공식 신고는 안전신문고에서 별도로 제출합니다.

## 주민 참여 기록 연결

GitHub Pages 배포본은 Supabase의 익명 로그인을 사용해 작성자를 구분합니다. 비밀번호나 이름을 받지 않습니다. 현장 기록과 순찰일지는 저장 즉시 공개되며, 공개 목록(`reports_feed`, `patrols_feed`)에는 작성자 번호를 내보내지 않습니다. 같은 사람의 기록끼리 묶이면 산책 경로로 사는 곳을 짐작할 수 있기 때문입니다. 다른 사람의 순찰일지는 시작·종료 시각을 그날 0시로 잘라 날짜만 보여 줍니다. 정확한 시각이 쌓이면 매일 걷는 시간대가 드러나기 때문입니다. 문제가 있는 기록은 관리자가 Supabase 표 편집기에서 내립니다. 현장 기록은 `reports.moderation_status`를 `rejected`로, 순찰일지는 `patrols.hidden`을 `true`로 바꿉니다. 지우지 않으므로 되돌릴 수 있습니다.

1. Supabase 프로젝트에서 익명 로그인을 허용합니다.
2. SQL 편집기에서 `supabase/schema.sql`을 실행합니다.
3. GitHub Actions 변수 `SUPABASE_URL`과 비밀값 `SUPABASE_ANON_KEY`를 등록합니다.
4. `Publish Smart Petrol`을 실행해 다시 배포합니다.

공개 가능한 publishable/anon 키만 사용합니다. 관리자용 service role 키는 브라우저나 GitHub Pages 빌드에 넣지 않습니다. Row Level Security가 승인 기록과 작성자 본인의 기록만 조회하도록 제한합니다.

## 실행과 빌드

Node.js 22.13 이상에서 `npm ci` 후 다음을 실행합니다.

```sh
npm run check
npm run lint:app
npm test
npm run build:pages
npm run test:pages
```

배포 대상은 `site-static/`입니다. 앱 코드는 분할하고, 공공데이터는 지역별 gzip 파일로 압축해 모바일 다운로드를 줄였습니다. 최신 Chrome·Edge·Safari가 필요합니다. 배경지도에는 인터넷 연결이 필요합니다.

`npm run dev`와 `npm run build`는 별도로 보존한 서버형 원본을 위한 명령입니다. 서버형 원본의 `/api/records`와 D1·플랫폼 인증은 GitHub Pages에서 실행되지 않습니다. 서버형을 다른 호스팅으로 옮기려면 검증된 로그인과 DB를 연결해야 합니다. 기존 Sites 프로젝트 ID는 이 저장소에서 제거했습니다.

## API와 매일 갱신

GitHub Actions 비밀값 `GG_API_KEY` 한 개를 경기데이터드림 네 API에 사용합니다. 시군별 반려견·반려묘 누적 현황은 농림축산식품 공공데이터포털에서 별도로 발급한 `MAFRA_API_KEY`를 사용합니다.

| 자료 | API 서비스명 |
| --- | --- |
| CCTV 위치 | `CCTV` |
| 보안등 위치 | `SECRTLGT` |
| 반려동물 등록 | `AnimalRegistStus` |
| 시군 보안등 종류별 집계 | `Secrtlgt` |
| 반려견·반려묘 누적 등록 | `Grid_20210806000000000612_1` |

`SECRTLGT`와 `Secrtlgt`는 대소문자가 다른 별개 자료입니다. API 키는 HTML·공개 소스·로그에 넣지 않습니다. 누적 동물등록 API는 등록·승인된 운영자료를 축종별로 합산하며 사망 개체가 포함될 수 있으므로 현재 사육 개체 수로 표시하지 않습니다.

GitHub 실행 환경에서 1,000행 응답이 시간 초과되는 현상을 확인해 250행씩 수집합니다. 요청은 최대 4개씩 병렬 처리하며 한 페이지가 끝내 실패하면 대기 요청을 취소합니다. 작은 API 요청을 비교하는 수동 연결 진단 작업도 포함했습니다.

공개 파일을 정규화하기 전에 기존 대비 좌표 건수 10% 이상 급감 여부를 검사합니다. 급감 시 기존 지도 파일을 유지하고 검토를 요청합니다. 이 비율은 프로젝트의 배포 검토 기준이며 공인 데이터 품질 기준이 아닙니다.

`Publish Smart Petrol` 작업은 소스 갱신, 수동 실행, 매일 한국시간 오전 6시에 작동합니다. 전체 페이지 수집 → 데이터 정리 → 점검 후보 계산 → 검사 → 공개 파일 빌드 → 배포를 순서대로 수행합니다. 어느 단계든 실패하면 배포하지 않아 기존 사이트가 유지됩니다. 예약 실행은 GitHub 사정으로 지연되거나 누락될 수 있습니다.

수집한 최신 자료는 그 실행의 배포 파일과 7일 보관 자료에 들어가며 소스 저장소에 자동 커밋하지 않습니다. 따라서 저장소에 포함된 초기 자료와 현재 웹에 게시된 자료의 확인 시각은 다를 수 있습니다. 수동 실행의 `refresh_data=false`는 포함된 초기 자료로 재배포하는 복구 옵션이므로 일반 갱신에는 사용하지 마세요.

기존 AI 검토 메모는 원본 확인 시각이 같은 경우에만 표시합니다. 데이터가 갱신되면 오래된 메모를 숨깁니다. 자동 갱신 작업이 생성형 AI를 새로 호출하거나 범죄를 예측하지 않습니다.

## 해석과 출처

지도 그라데이션은 주변 8구획과 비교한 **등록 시설의 상대 부족 지표**이며, 검증된 범죄위험이나 실제 어두움의 지표가 아닙니다. 불충분한 지역 자료는 분석에서 제외하며 누락을 안전함으로 해석하지 않습니다. 실제 밝기·작동 상태·촬영 범위·보행 가능성은 현장 확인이 필요합니다.

조명 집계는 전력 구간별 개소 수이며 조도나 전기 사용량이 아닙니다. 노란빛만으로 노후·범죄위험을 판단하지 않습니다. 반려동물 수는 실제 순찰 참여자 수가 아닙니다.
